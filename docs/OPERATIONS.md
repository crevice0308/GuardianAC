# GuardianAC Ultimate 運用ガイド

## 対応範囲と導入時の確認

このソースは公開Spigot API 1.20.4を使います。そのAPIと互換性のあるSpigot／Paper／Purpurが対象ですが、派生サーバーや新しいMinecraft版すべての実測互換性を示すものではありません。Foliaの地域スケジューラーは対象に含めていません。ビルドにはJDK 17以上、実行にはサーバーが要求するJavaを使います。PacketEvents等の追加プラグインは不要です。

旧版とこの版はともにプラグイン名が `GuardianAC` です。サーバーを停止して旧JARと `plugins/GuardianAC/` をバックアップ・退避し、JARを1つだけ導入してください。旧設定、SQLiteデータ、証拠、GUI等の移行処理はありません。旧データを捨てず、従来の制限をどこで維持するか確認してから切り替えます。サーバーのEULA同意やサーバー配布物の導入は、このビルド手順には含まれません。

## 検知からBANまで

移動はサーバーの各tick、攻撃はプレイヤー間の直接攻撃イベントから観測します。Speedは許容水平移動、Flyは支えのない滞空・上昇、Reachは目から対象の当たり判定までの距離、KillAuraは不自然な攻撃方向や攻撃・対象切替の集中を調べます。合法移動や遅延をすべて再現する物理シミュレーターではありません。

1. 検知ごとの `detection.*-buffer` で繰り返し観測を要求します。
2. 検知成立時に、検知の重みと `checks.<check>.weight` に応じて、そのプレイヤーの検知別VLへ加算します。
3. VLは `violations.decay-per-second` で減衰します。VLがゼロまで戻ると、その検知の検出回数・開始時刻も次の加算でリセットされます。
4. 同じ検知のVLが `checks.<check>.threshold` 以上となり、`minimum-findings` 回と `minimum-evidence-ticks` の両方も満たし、自動BANが有効な場合に保存を要求します。異なる検知のVLを合計して閾値を満たす方式ではありません。
5. BANの永続化が成功してから、現在接続中の該当プレイヤーを切断し、以後の接続を拒否します。保存失敗やキュー満杯では未保存のBANを適用しません。

`/gac vl` は検知別VLの最大値です。再起動、設定再読込、退出で検知状態はリセットされます。保存済みBANはこれらの操作では解除されません。

## 設定

設定先は `plugins/GuardianAC/config.yml` です。数値・真偽値には範囲検証があります。不正な設定での再読込は拒否され、直前に有効だった設定を使います。変更後は `/gac reload`、保存キュー容量の変更は再起動を使ってください。保存処理が進行中なら再読込を拒否するため、完了を待って再実行します。再読込ではVL・観測履歴・通知待機時間を初期化します。

| 設定 | 既定値・役割 |
| --- | --- |
| `punishment.auto-ban` | `true`。`false` なら検知・通知を続けながら自動処罰を止める |
| `punishment.mode` | `UUID_AND_IP`。`UUID` にすると自動処罰のIP制限を止める |
| `punishment.duration` | `24h`。`permanent` で永久。手動コマンドは指定した期間を使う |
| `punishment.reason` | `Unfair play: {check}` |
| `punishment.broadcast` | `true`。BAN適用後の全体通知 |
| `punishment.queue-capacity` | `256`。保存ワーカーの待機ジョブ数上限。変更には再起動が必要 |
| `violations.decay-per-second` | `0.75`。20tick換算のVL減衰量 |
| `violations.minimum-findings` | `6`。同一検知の最小加算回数 |
| `violations.minimum-evidence-ticks` | `40`。同一検知の観測開始から必要なtick数 |
| `violations.alert-cooldown-ticks` | `40`。プレイヤーごとの管理通知間隔 |
| `checks.speed`／`fly`／`reach`／`killaura` | `enabled`、`threshold`、`weight`。すべて既定で有効 |
| `detection.*` | 速度許容率、バッファ、滞空猶予、Reach余裕、攻撃角度・頻度・対象数・観測窓 |
| `safety.*` | Ping・tick遅延の上限、各種猶予、基本速度・Reach上限、遅延余裕、履歴上限、共有IP軽減 |

`threshold` を下げる／`weight` を上げるとVL条件を早く満たしますが、最小回数・証拠期間・検知バッファも必要です。一項目だけを変えてBANまでの時間を断定できません。校正時はまず `auto-ban: false` と管理通知で通常操作を確認し、その後に各値を調整します。

期間は正の整数と単位 `s`・`m`・`h`・`d`・`w`、または `permanent` です。例は `30m`、`24h`、`7d`。ゼロ・負数・小数・複合期間・オーバーフローは拒否します。期限の表示はUTCです。

### 誤検知軽減

既定ではPing 250ms超、tick間隔80ms超とその後40tick、参加後60tick、テレポート後40tick等に猶予を設けます。ノックバック等の速度変更・被ダメージの直後にも移動猶予があります。飛行可能状態、Creative／Spectator、エリトラ、泳ぎ、乗り物、浮遊等や、氷・液体・スライム・ハチミツ・ピストン等の特殊な周辺ブロックも除外に使います。

Reachには上限付きの遅延余裕を加え、対象の短い位置履歴から合法とみなせる最短距離を使います。履歴はプレイヤーを処罰しやすくするためには使いません。猶予・除外は誤検知を減らす一方、検知できない期間も増やします。独自ノックバック、移動能力、特殊武器、プロキシ構成は実環境で確認してください。

攻撃角度にも同じ対象履歴を使い、近距離で対象が正面から背後へ移動する場合の誤検知を軽減します。被害者の除外権限や移動用ポーションは、攻撃者の戦闘検知を無効にしません。Jump Boost・Slow Falling・LevitationはFly判定だけを免除し、Speedの水平移動観測は続けます。階段・ハーフブロックなど複雑な足場付近は、単純な当たり判定で誤処罰しないよう移動判定を免除します。

### IP制限

自動IP BANのアドレスはBukkitが提供する接続元です。`protect-shared-ip: true` は、同じアドレスの**別UUIDが現在オンラインのときだけ**UUID BANに縮退します。過去の利用者、オフラインの家族、学校、会社、VPNなどの全利用者を把握する仕組みではありません。手動 `/gac ipban` は管理者が指定したUUIDとIPを制限し、この自動縮退の対象にはなりません。

信頼できるUUID／IP転送はサーバーとプロキシ側で構成します。バックエンドへの直接接続を遮断し、信頼できるプロキシだけに転送を許可してください。IPを確認できない構成では自動処罰を `UUID` にします。IP BANは同一IPの他のアカウントにも影響します。

### チャット演出

`messages.*` には従来の `&` 色コードを使えます。BAN全体通知は `messages.ban-broadcast` の行リストを変更します。

| 設定先 | プレースホルダー |
| --- | --- |
| `messages.alert` | `{player}`、`{check}`、`{vl}` |
| `messages.ban-screen` | `{player}`、`{reason}`、`{expires}`、`{id}` |
| `messages.ban-broadcast` | `{player}`、`{reason}`、`{expires}`、`{id}`、`{check}` |
| `punishment.reason` | `{check}` |

## コマンドと権限

`/guardian` と `/gac` は同じです。コンソールでも管理できますが、通知の切替だけはプレイヤー専用です。手動BANとVL参照の対象はオンライン名です。UNBANにネットワーク上の名前解決や外部アカウント照会は使いません。

| コマンド | 権限 | 内容 |
| --- | --- | --- |
| `/gac`、`/gac status` | `guardianac.view` | 稼働状態・保存状態・検知数・モード・tick遅延・保存待ち |
| `/gac vl <オンライン名>` | `guardianac.view` | 現在の最大検知別VL |
| `/gac bans [ページ]` | `guardianac.view` | 有効なBANを8件ずつ表示。IPの数値は表示しない |
| `/gac alerts` | `guardianac.alerts` | 自分への検知通知をセッション単位で切替 |
| `/gac reload` | `guardianac.admin` | 設定を検証して再読込 |
| `/gac ban <オンライン名> <期間> [理由]` | `guardianac.ban` | UUID BAN |
| `/gac ipban <オンライン名> <期間> [理由]` | `guardianac.ipban` | UUIDと現在の接続元IPをBAN |
| `/gac unban <名前\|UUID>` | `guardianac.unban` | 該当する保存済みBANと、そのBANに紐付くIP制限を解除 |
| `/gac unbanip <数値IP>` | `guardianac.unban` | 該当IPの制限だけを解除。UUID BANは残る |

上記権限はすべて既定でOPです。権限は個別で、`guardianac.admin` だけではBANやUNBAN権限を兼ねません。検知除外の `guardianac.bypass` は既定で無効で、OPにも自動付与されません。BAN一覧や管理権限は必要なスタッフにのみ付与してください。

名前指定UNBANは保存済みの名前で照合するため、名前変更・過去の同名利用がある場合はUUIDを使います。IP指定はIPv4／IPv6の数値リテラルだけで、ホスト名・CIDR・範囲指定は使えません。GuardianACの解除はサーバー標準BANや他プラグインの制限を解除しません。

## 保存・期限・復旧

`plugins/GuardianAC/bans.json` が専用保存ファイルです。BANのUUID、名前、IP制限、理由、作成元、期限等を扱います。更新は非同期の単一ワーカーへ送り、同じディレクトリの一時ファイルへ書いてから置換します。メモリー上の有効状態も保存成功後に更新するため、保存失敗では未保存の処罰・解除を適用しません。

期限切れのレコードは接続拒否・有効BAN一覧から除かれますが、履歴としてJSONに残ります。自動の保存期間削除やバックアップ世代管理はありません。IPは保護すべき接続情報です。サーバーの実行ユーザーに必要なファイルアクセスだけを与え、データディレクトリ・退避コピー・バックアップの閲覧権限と保存期間を運用側で管理してください。ファイル共有や障害報告で中身を公開しないでください。

起動時の設定・BANファイル読込に失敗した場合は、破損ファイルを上書きせず、新しいログインを拒否する状態で停止します。`/gac status` とサーバーログを確認し、サーバーを停止して元ファイルを保全します。設定を修正するか、管理したバックアップから `bans.json` を復元してから再起動してください。この状態は `/gac reload` だけでは復旧しません。データを空にしてエラーを回避すると既存の制限を失います。

実行中に保存が失敗した場合は、その処罰・解除の失敗がログに残ります。既存の有効なBANは維持し、ディスク容量・権限・一時ファイルの作成可否を修正して再操作します。キュー満杯では新しい保存要求を拒否するため、`/gac status` とエラーを確認してください。終了時は保存ワーカーの完了を待ちます。強制終了や待機タイムアウトがあった場合は再起動前にファイルを確認します。

## 性能と検証

通常の観測処理はオンライン人数に比例する各tickの走査です。各プレイヤーの周辺ブロック確認は狭い範囲に限り、未ロードのチャンクを検知のために読み込みません。検知エンジンは上限のある履歴・窓を使い、各観測の処理量を制限します。Bukkitのワールド・プレイヤー参照はメインスレッド、ファイル書込みは上限付き非同期キューに分けています。

BAN照合は不変スナップショットを読むため、保存ワーカーのディスク書込みロックを待ちません。JSON保存は全レコードの再書込みで、64MiBの上限があります。BAN履歴が巨大になると保存時間・メモリー・共有IPの期限照合コストが増えます。上限付きキューは過負荷の無制限蓄積を防ぎますが、大規模本番環境での性能保証ではありません。実際の人数、履歴サイズ、CPU、ディスクでtick時間と保存遅延を測定してください。同じディレクトリ内での原子的置換をサポートするファイルシステムが必要です。

ビルドと自動テストは次のコマンドです。初回は公開Maven／Spigotリポジトリから依存を取得します。

```sh
./mvnw -B verify
```

Java 17／21で154件の自動テストが成功しました。Paper 1.20.4 #499とPurpur 1.20.4 #2176で、それぞれ実サーバー10項目（BAN/IPBAN、接続拒否、期限切れ、永久BANの再起動保持、UNBAN、実際のFly自動BANと名前付き告知）が成功しています。[検証記録](VALIDATION.md) に再現手順と未検証範囲を記載しています。

本番導入前には通常移動・実対戦、遅延、独自の特殊ブロックや能力、大人数負荷を追加確認してください。自動テストとローカル検証だけでは実対戦での誤検知率や全サーバー版の互換性は確定しません。
