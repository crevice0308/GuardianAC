# GuardianAC Ultimate 1.0.0 — 総合開発依頼書

## 1. 開発目的

Minecraft Java Edition向けの高性能アンチチートプラグイン「GuardianAC Ultimate」を新規開発してください。

本プロジェクトは、完全無料・オープンソース・前提プラグイン不要・Zero Configを基本理念とします。

**最重要コンセプト：**

「導入するだけでチートを検知し、確実な不正行為を自動BAN。複雑なConfig編集を必要としない総合アンチチート」

開発途中の機能限定版を正式リリースせず、以下の全機能を搭載した1.0.0の完成を目指してください。

内部開発は段階的に進めて構いませんが、正式公開は全機能の実装・検証が完了してからにしてください。

## 3. チート検知エンジン

イベント監視とパケット解析を組み合わせたハイブリッド型検知エンジンを実装してください。

目標は50種類以上の独立した検知モジュールです。

### 戦闘系

KillAura、AimBot、Reach、AutoClicker、TriggerBot、Criticals、Velocity、HitBox、AutoTotem、不自然な攻撃間隔、不正な視線移動など。

### 移動系

Fly、Speed、BunnyHop、Jesus、Spider、Step、NoFall、NoSlow、Phase、AirJump、ElytraFly、不正な加速度、異常な移動パケットなど。

### 採掘・建築系

FastBreak、FastPlace、Nuker、Scaffold、Tower、BedBreaker、AutoTool、不自然なブロック破壊・設置など。

### インベントリ系

InventoryMove、ChestStealer、InventoryCleaner、AutoArmor、異常なインベントリ操作など。

### 通信系

Timer、Blink、BadPackets、PacketFlood、異常なパケット頻度、プロトコル違反など。

各検知は独立したモジュールとして実装し、GUIから個別に有効化・無効化できるようにしてください。

単なる名称だけのダミー検知は禁止です。各モジュールに実際の判定処理、テスト、誤検知対策を実装してください。

## 4. X-Ray対策

以下を標準搭載してください。

- 鉱石情報の隠蔽
- 不自然な採掘経路の分析
- 希少鉱石発見率の分析
- 採掘履歴と証拠保存
- 洞窟・地下情報の保護
- GUIからの設定変更

Paper / Purpurでは既存のAnti-Xray機能との二重処理を避けてください。

Spigotでは互換性のある独立した対策を検討してください。

サーバー側から直接観測できないクライアント側の透視機能については、対策可能な範囲と限界を明示してください。

## 5. VL（Violation Level）

標準設定はSTRICTモードとしてください。

- 厳格な不正検知
- 違反の継続に応じたVL加算
- 正常行動によるVL減衰
- 検知種別ごとのしきい値
- Ping・TPS・ポーション・ノックバック・乗り物などの考慮
- 複数の独立した検知結果による確信度評価
- GUIから感度調整
- NORMAL / STRICT / RELAXEDプリセット

自動BANは単純なVL値だけで決めず、証拠の確信度も使用してください。

## 6. 自動BANシステム

通常のチート検知による自動KICKは実装しないでください。

制裁の基本フロー：

検知 → VL蓄積 → 証拠検証 → 自動BAN

実装対象：

- 自動UUID BAN
- 自動IP BAN
- UUID + IPのDUAL BAN
- 期限付きBAN
- 永久BAN
- BAN回避検知
- 共有IP保護
- 自動BAN理由の記録
- ケースIDの発行
- 管理者によるBAN解除
- BAN履歴の保持

自動IP BANは高確信度の違反や反復したBAN回避など、追加条件を満たす場合に実行してください。

IP BANの期間は1時間・24時間・7日・30日・永久から選択可能にしてください。

永久IP BANの自動適用は共有回線への影響を考慮した厳格な追加条件を必要とします。

## 7. 専用BANデータベース

GuardianAC専用のSQLiteデータベースを作成してください。

想定構成：

plugins/GuardianAC/bans/bans.db

記録項目：

- UUID
- プレイヤー名
- IP情報
- BAN種別
- BAN理由
- BAN日時
- 解除予定日時
- 永久BANフラグ
- 違反レベル
- ケースID
- 証拠参照
- BAN実行者
- UNBAN履歴

Minecraft標準BANリストとの同期にも対応してください。

他の管理者やプラグインが登録したBANを誤って解除しないよう、GuardianACが所有するBAN記録を区別してください。

データ破損への復旧策、バックアップ、原子的な保存、保存期間、IP情報の保護も実装してください。

## 8. UNBANシステム

以下の操作を実装してください。

- `/gac unban <player>`
- `/gac unban <case-id>`
- `/gac unbanip <ip>`
- `/gac unbanall <player>`

チェスト型GUIからも操作可能にしてください。

解除前に確認画面を表示し、解除者・日時・理由を記録してください。

UNBAN時は対象の古いVLをリセットし、過去の証拠は保持してください。

## 9. チェスト型管理GUI

`/guardian` または `/gac gui` で開ける54スロットのGUIを実装してください。

デザインは黒曜石をイメージした高級ミニマル型です。

メインメニュー：

1. 検知管理
2. プレイヤー監視
3. BAN / IP BAN管理
4. UNBAN管理
5. 違反履歴
6. 証拠・リプレイ
7. X-Ray対策
8. Discord通知
9. システム設定

GUIからほぼすべての設定を変更できるようにしてください。

設定変更は自動保存し、可能な範囲で再起動不要としてください。

各項目のLoreには日本語で分かりやすい説明を表示してください。

管理権限と閲覧専用権限を分離し、クリック操作によるアイテムの持ち出しや不正操作を防止してください。

## 10. オリジナルBAN演出

デザインは「高級ミニマル型」。

使用色：

- 白
- グレー
- 深紅

BAN画面の基本表示：

GUARDIANAC ULTIMATE

ACCESS REVOKED

Your access to this server has been revoked.

REASON: Unfair Advantage

STATUS: PERMANENT BAN

CASE ID: GAC-XXXXXXXX

BANされたプレイヤーの切断画面、管理者通知、全体チャット通知をそれぞれ実装してください。

全体チャットではBANされたプレイヤー名を表示してください。

例：

[GuardianAC] ExamplePlayer has been permanently banned.

Reason: Unfair Advantage

Server integrity maintained.

一般プレイヤーには詳細な検知ロジックを公開せず、管理者にのみ詳細情報を表示してください。

連続BAN時の通知スパム防止機能も実装してください。

## 12. Discord連携

Discord連携は任意機能です。

初期状態はOFF。

Webhook URLは管理者が手動登録する方式にしてください。

通知内容：

- 自動BAN
- IP BAN
- 重大な不正検知
- Bot攻撃
- クラッシュ攻撃
- システムエラー

Webhook URLをログやGUIへ平文で表示しないでください。

Discord連携を使用しなくても、アンチチート本体の全機能が動作するようにしてください。

## 13. Zero Config

プラグインJARをpluginsフォルダへ配置して起動するだけで、基本的な検知・防御が開始される設計にしてください。

設定ファイルは自動生成してください。

外部プラグイン、外部データベース、外部APIへの接続を必須にしないでください。

高度な設定はGUIから変更できるようにしてください。

## 14. パフォーマンスと互換性

- メインスレッドの負荷を最小限に抑える
- 重いログ処理は適切に非同期化する
- Bukkit APIのスレッド安全性を守る
- メモリリークを防止する
- 大量プレイヤー環境での負荷テストを行う
- TPS低下時の誤検知を抑制する
- Spigot / Paper / Purpurで動作検証する
- 他のプラグインとの競合を調査する
- サーバー再起動後もBAN状態を維持する
